Daily Dev Log

Turn your local AI coding sessions into a short, factual build-log post every day, and a private Obsidian second brain that remembers what you shipped and what's still open. Transcripts stay on your machine.

Open on GitHub → Read the log → Start your own →

What it does

A local CLI reads the session logs your coding agents already keep, then writes two things. The public log says what kind of work happened. The private vault keeps everything.

Public

A post a day

Minutes, projects, kinds of work, commits shipped, and your stack, published to GitHub Pages every night. Quiet days are skipped.

Privacy

You choose what leaves

Three detail levels (summary, projects, verbatim) and your own redaction patterns for identifiers such as MRNs or sample IDs. The default never quotes your prompts.

Obsidian

A linked second brain

Day notes link to project, work-type, and topic hubs, plus weekly, monthly, and quarterly rollups, streaks, a heatmap, Bases views, and per-project canvases.

Follow-through

What's still open

"Next steps" from your agents' recaps become checkboxes that stay ticked. Your commits, related days, repo README, and open PRs sit alongside them.

Agents

Memory over MCP

devlog mcp lets Claude Code or Codex ask what you did on a project last week, and what you left unfinished.

Local-first

Nothing leaves by default

Parsing, classification, topics, similarity, and cost estimates all run locally. Optional Ollama models add semantic links and retros on your own machine.

Start your own

Your posts live in a GitHub repo of your own, separate from the tool, so updating devlog never touches them. You need Python 3.11+, git, and a GitHub account. Full walkthrough, including Windows PowerShell: README → Start your own log.

  1. Install the tool

    pipx install "daily-devlog[mcp] @ git+https://github.com/musicofthings/devlog"

  2. Create a site repo

    Make an empty GitHub repository (devlog gives you https://<you>.github.io/devlog/), clone it, and add the site skeleton: two workflows, the log's stylesheet and script, and a landing page.

    git clone https://github.com/<you>/devlog.git && cd devlog
base=https://raw.githubusercontent.com/musicofthings/devlog/main
mkdir -p .github/workflows docs/assets
for f in .github/workflows/pages.yml .github/workflows/delete-post.yml \
         docs/assets/theme.css docs/assets/theme.js; do
  curl -fsSLo "$f" "$base/$f"
done
printf '<meta http-equiv="refresh" content="0; url=log/">\n' > docs/index.html
git add . && git commit -m "Add devlog site skeleton" && git push

    Then turn on Settings → Pages → Source: GitHub Actions.

  3. Configure it inside the site repo

    devlog init     # sources, publish mode, privacy level, vault, nightly schedule
devlog doctor   # each problem prints its fix

    Start with publish_mode = "review". The default privacy level, projects, never quotes your prompts; add redact_patterns for identifiers such as MRNs or sample IDs.

  4. Publish

    devlog publish --dry-run --explain         # preview yesterday's post
devlog publish                             # write it (review mode: no push yet)
devlog publish --confirm --date YYYY-MM-DD # push it

    Your log goes live at https://<you>.github.io/devlog/log/. After that, the nightly job devlog init sets up (Task Scheduler on Windows, launchd on macOS, cron on Linux) publishes each day for you.
